## 1. プロジェクト概要

写真家「hono」のブランドサイト。作品集ではなく、写真家としての世界観・価値観が伝わるポートフォリオサイトを目指す。営業色は排し、作品そのものを主役にする。

- 目的: 写真作品の公開、ブランド構築、業界関係者・メーカー担当者への訴求、長く育てられるサイトの構築
- 想定読者: 写真好き、写真業界関係者、写真メーカー担当者、将来展示や作品制作で関わる可能性のある人
- 技術要件: Next.js / TypeScript / App Router / コンポーネント設計 / レスポンシブ対応 / GitHub管理
- CMS: Kuroco（作品・実績・プロフィール文・お問い合わせを管理）
- 公開先: GitHub Pages（`https://hono-hono.github.io/photographer/`）。独自ドメインは使わない

## 2. コンセプト

被写体: 廃線・廃墟・古い建物・人の面影を感じられる風景
写真観: 派手な絶景ではなく、その場所に残された空気・物語・静かな時間を記録する
人物像(サイトの雰囲気づくりの根拠。画面には文章として載せない): 一人で行動することを好む、自分らしさを大切にする、興味を持ったことは徹底的に調べる、合理的、行動力がある

サイト全体の方針: 「写真集をめくるような静かな体験」。装飾は最小限、過度なアニメーション・パララックス・動画背景・派手なエフェクトは避ける。

**デザインは被写体の雰囲気(廃墟・経年感)を直接踏襲しない。** honoさん自身の感性(無印良品・ユニクロ・GU的なシンプルさ、ミッフィーに通じる柔らかさ、北欧インテリアの落ち着き)を出発点とし、「一見主張がないのに、実はきちんと作り込まれている」というギャップを、色ではなく書体・余白・動き・パーツの形で表現する。

## 3. デザイン方向性(トンマナ) — 確定

### 配色
無彩色(白・黒・グレーの階調)のみを使用し、色による装飾は行わない。作品の色そのものが最も目立つようにするための判断(参考: sara2626.com、studio.siteのworksページ)。差し色は設けず、必要であればグレーの濃淡のみでリンクのフォーカス状態などを表現する。

| 用途 | 値 |
|---|---|
| 背景 | #F7F7F6 |
| パネル・入力欄 | #FFFFFF |
| 文字(主) | #1C1C1A |
| 文字(副) | #4A4A47 |
| 補助文字 | #8C8C89 |
| 罫線 | #D9D9D6 |
| タイル・ボタン背景 | #F1F1EF |

### タイポグラフィ
- 見出し・ロゴタイプ: Noto Serif JP(明朝体)、字間を広めに、太さはレギュラー〜ミディアム(可読性を優先し細すぎるウェイトは使わない)
- 本文・キャプション・UI: Noto Sans JP(ゴシック体)、レギュラーウェイト
- 選定理由: 環境を問わず均質に表示される最も普遍的な組み合わせであり、「長く使えるサイト」という要件に合致する。フォントファミリーを絞ることで実装・保守もシンプルになる

### 「らしさ」を宿す要素(色を使わない代わりに)
1. **余白**: 写真集の版面のように、通常のポートフォリオサイトより広めの余白を取る
2. **動き**: 控えめで一方向的な動きのみ使用(スクロールでの静かなフェードイン、ナビゲーションのアンダーラインが滑らかに伸びる、程度)。写真のホバー演出、タブ切り替え、作品の前後移動には演出を入れない。要件定義の「過度なアニメーションを避ける」の範囲内に収める
3. **かたち**: 写真自体は直角のまま装飾しない。丸みによる柔らかさは写真以外のUI要素(ボタンの背景など。角丸の値は案として10px)で表現する

## 4. サイト構成 — 確定

3ページ構成。Profile と Contact は独立ページにせず、トップの中に置く。

| ページ | URL | 内容 |
|---|---|---|
| トップ | `/` | MV → 「すべての写真を見る」ボタン → Profile → Contact |
| Gallery | `/gallery?category=all\|works\|family\|anniversary` | 下層ページ。タブで絞り込み |
| 作品詳細 | `/gallery/[slug]` | Gallery の下層。写真だけを大きく表示 |

### 共通パーツ
- **ヘッダー: 画面上部に固定。** 高さは PC 48px / SP 44px 程度。左にロゴ「hono」、右にナビ3項目(Gallery / Profile / Contact)。「Home」の項目は置かず、ロゴがトップへの戻りになる。SPは右上に文字の「Menu」ボタン(アイコンなし)。押すとヘッダーの下に3項目が縦に並び、項目を選ぶと閉じる。ヘッダーの色・背景は背景(#F7F7F6)と同じ色に、下端へ 1px の罫線(#D9D9D6)。スクロールで写真が下に回り込んでもロゴとナビが読めるようにする(2026-11-01 決定)
- Profile / Contact はトップ内の `/#profile` `/#contact` までスクロールする。Gallery・作品詳細からはトップへ移動してから該当位置に進む。固定ヘッダーに見出しが隠れないよう、止まる位置を高さの分だけずらす。トップでは、いま画面にあるセクションのナビ項目に下線がつく
- **フッター:** 1行。左に「© hono」、右に「Coconala ↗」(https://coconala.com/users/2362314、新しいタブで開く)
- 余白の案: 左右 PC 64px / SP 20px、セクション間 PC 120px / SP 72px、基準単位 8px

## 5. ページ別仕様

### 5.1 トップ(`/`)

- **MV(メインビジュアル):** 代表作10枚を、高さをそろえた行で並べる。1行の中の写真は高さが同じで、幅は元の縦横比のまま。行の左右の端もそろう。Galleryと同じ並べ方で、同じ部品を使い回す。PCは3行(4枚・3枚・3枚)、SPは5行(各2枚)。左右の余白の内側に収める
- 写真に角丸は使わず直角のまま。切り抜かない。写真の上に文字を重ねない
- ホバー時の反応: なし
- **写真を押すと拡大表示(重ね表示で決定)。** トップの上に暗い面を重ね、写真だけを大きく見せる(文字は出さない)。前後移動はMVの10枚の中だけ(PCは写真の左右に矢印と矢印キー、SPは写真の下にPrev / Next)。閉じ方は「✕ 閉じる」、Esc、写真の外側を押す。閉じるとトップの元の位置に戻る
- **「すべての写真を見る →」ボタン**をMVのすぐ下の中央に置く。遷移先は `/gallery?category=all`。カテゴリ別のボタンはトップに置かない(絞り込みはGalleryのタブで行う)
- 一行ステートメントは置かない(決定)。考えは Profile のリード文で伝える

### 5.2 Gallery(`/gallery`)

- 下層ページ。カテゴリごとにページ遷移させず、タブで同一ページ内完結
- タブの上に明朝の見出し「Gallery」を置く(デザイン初版で決定)
- タブ構成: All / Works / Family / Anniversary。初期表示は All(全作品をまとめたグリッド)
- タブ切り替え: フェード等の演出なし、瞬時にグリッドが絞り込まれる
- 実装: ARIAのtablist/tabpanelパターン。矢印キーでのタブ間移動に対応
- URL連動: `/gallery?category=all|works|family|anniversary`。クエリなしアクセスは all 扱い。特定カテゴリを直接リンクで共有可能にする
- **写真は切り抜かず元の縦横比のまま並べる。** 1行に並ぶ写真の高さをそろえ、幅は写真ごとに変える(縦位置は細く、横位置は広くなる)。目安は PC 3〜4枚 / SP 2枚。キャプションは付けず、クリックで作品詳細へ。各写真の幅と高さをデータに持たせ、読み込み中にレイアウトが動かないようにする
- 作品詳細からブラウザの戻るで帰ったときは、選んでいたタブとスクロール位置を復元する

### 5.3 作品詳細(`/gallery/[slug]`)

- **写真だけを大きく見せる。** タイトル・区分・年・撮影場所・撮影情報・「12 / 24」のような枚数表示は載せない
- 写真は画面の高さに収まる大きさで、縦位置も横位置も切らず全体を表示する
- 戻る手段は写真の上の小さな「← Gallery」だけ(元のタブとスクロール位置に戻る)
- 前後の作品への移動: いま見ているカテゴリの中だけ。PCは写真の左右に矢印、矢印キー操作にも対応。SPは写真の下に Prev / Next
- 遷移演出(フェード・スライド等)は入れない
- 写真の代替テキスト(画面には出ない短い文)を各作品に付ける

### 5.4 Profile(トップ内 `#profile`)

- 配置: PCは左にポートレート(縦位置)、右に文章。SPは見出しの下にポートレート(横長)、その下に文章
- 構成: 見出し「Profile」→ 明朝のリード文(1〜2文)→ 「写真歴」の本文 → 実績
- 写真歴: **2013年から**撮影を始めた。本文は「写真歴」の1ブロックだけ。「被写体との向き合い方」と「人物像」は載せない。リード文・本文は既存の要件定義テキストをベースに再構成する
- **文面(2026-11-01 決定)**。文体は敬体
  - リード文(明朝): そこにいた人の気配や、営まれていた暮らしを想像できる風景に惹かれています。写真を見る人にも、その場所に流れていた時間を感じてもらえたらうれしいです。
  - 写真歴: 2013年に撮影を始めました。派手な絶景よりも、廃線や廃墟、古い建物に残された空気や物語を、静かに記録することを大切にしています。
- **実績**(「時期・内容」の行リスト。区分ごとにまとめ、区分の中は新しい順。年月が分からない行は年月の欄を空ける。行と区分を足すだけで済む部品にする):
  - 受賞・選出
    - 2025年5月 第63回 富士フイルムフォトコンテスト 最終選考通過
    - 2023年10月 若手写真家支援写真展 2023/2025 ファイナリスト(「2023/2025」は年度の表記。本番は年度と分かる書き方にする案)
    - OM・新人写真家発掘プロジェクト・ライムライト ファイナリスト
    - 第23回全動物写真コンテスト 準優秀賞
    - GANREF TODAY'S PHOTO 選出
  - 講演・活動
    - 現在 カメラのキタムラ写真教室 岡山版 現役アシスタント
    - 2023年12月 OM SYSTEM GALLERY 刻景 × 私の未来は(講演)
  - 資格
    - フォトマスター検定 2級
- 載せないもの: 展示歴・企画展・グループ展(師匠の経歴のため)、使用機材

### 5.5 Contact(トップ内 `#contact`)

- お名前・メールアドレス・お問い合わせ内容(フリーテキストのみ)のミニマルなフォーム
- 問い合わせ種別の選択(取材/展示/購入など)は設けない。営業色を出さない方針を最優先
- 縦1列、ラベルは入力欄の上。幅は約480pxに絞る。冒頭に1〜2行の短い案内文
- **文面(2026-11-01 決定)**。文体は敬体
  - 案内文: 撮影のご相談や作品について、お気軽にお問い合わせください。
  - 自動返信メール(送信した人に届く):
    ```
    件名: お問い合わせを受け付けました ｜ hono

    {お名前} 様

    このたびはお問い合わせいただき、ありがとうございます。
    以下の内容で受け付けました。内容を確認のうえ、あらためてご連絡いたします。

    ――――――――――
    お名前：{お名前}
    メールアドレス：{メールアドレス}
    お問い合わせ内容：
    {お問い合わせ内容}
    ――――――――――

    ※このメールは送信専用のアドレスから自動で送っています。ご返信いただいても届きませんので、ご了承ください。

    hono
    photographer.hono@gmail.com
    https://hono-hono.github.io/photographer/
    ```
  - 返信の日数の目安は書かない。※の一文は、Kuroco で返信を受け取れる設定にできた場合は削る
- 送信後はページ内の文面に置き換える(ページ移動なし)。入力ミスはその項目の直下に文章で伝える
- 送信先は Kuroco のフォーム機能(詳細は `hono_component_design.md` 7.6)。通知は photographer.hono@gmail.com に届く
- フォームの下に連絡先のメールアドレス(photographer.hono@gmail.com)を文字で表示する(決定)。押すとメールアプリが開くリンクにする
