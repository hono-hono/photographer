## 1. プロジェクト概要

写真家「hono」のブランドサイト。作品集ではなく、写真家としての世界観・価値観が伝わるポートフォリオサイトを目指す。営業色は排し、作品そのものを主役にする。

- 目的: 写真作品の公開、ブランド構築、業界関係者・メーカー担当者への訴求、長く育てられるサイトの構築
- 想定読者: 写真好き、写真業界関係者、写真メーカー担当者、将来展示や作品制作で関わる可能性のある人
- 技術要件: Next.js / TypeScript / App Router / コンポーネント設計 / レスポンシブ対応 / GitHub管理

## 2. コンセプト

被写体: 廃線・廃墟・古い建物・人の面影を感じられる風景
写真観: 派手な絶景ではなく、その場所に残された空気・物語・静かな時間を記録する
人物像: 一人で行動することを好む、自分らしさを大切にする、興味を持ったことは徹底的に調べる、合理的、行動力がある

サイト全体の方針: 「写真集をめくるような静かな体験」。装飾は最小限、過度なアニメーション・パララックス・動画背景・派手なエフェクトは避ける。

## 3. デザイン方向性(トンマナ) — 未確定・3案

作品画像を見た上で最終決定する。いずれも「明朝(見出し)×ゴシック(本文)」の二軸構成、装飾色は最小限に絞る方針は共通。

### 案A: 生成り(きなり)
- 背景 `#EFEBE3` / 墨 `#1E1C19` / 灰 `#8B857A` / 錆(アクセント) `#9C6B4F` / 苔(第二アクセント) `#6B6E5C`
- 印象: 古い紙の温度感。人の暮らしの痕跡というテーマに寄せた案

### 案B: 銀塩(ぎんえん)
- 背景 `#F4F4F2` / 中間灰 `#8C8C88` / 墨 `#151513`。色付きアクセントなし(無彩色のみ)
- 図版番号・撮影データはモノスペースフォント(EXIF的な客観性)
- 印象: 白黒プリントの階調そのもの。「装飾は最小限に」を最も厳格に解釈した案

### 案C: 苔衣(こけごろも)
- 背景 `#E9E7DD` / 苔色(アクセント) `#5C6350` / 墨 `#20221C`
- 印象: コンクリートに苔が生した廃墟のトーン。案Aより冷たく、時間の積もった空気を強めに表現

### タイポグラフィ(共通方針)
- 見出し・ロゴタイプ: 明朝体(例: Shippori Mincho) — 字間を広めに
- 本文・キャプション・UI: ゴシック体、細め〜レギュラー(例: Zen Kaku Gothic New)

## 4. サイト構成

Home / Gallery(All・Works・Family・Anniversary をタブ切り替え) / Profile / Contact

## 5. ページ別仕様

### 5.1 Home

- MV(メインビジュアル): 静止したグリッド。代表作10枚を厳選使用
- グリッドは不揃いなマス目(大小のリズム)で構成し、動きをつけずに視覚的なリズムを出す
- ホバー時の反応: なし(クリックで遷移のみ)。演出よりも作品鑑賞を優先する判断
- MV中央に一言コピー(最小限のテキストのみ、作品を隠さない配置)
- MV下部にWorks / Family / Anniversaryへのリンクを配置(遷移先はGalleryの該当カテゴリ、`/gallery?category=...`)

### 5.2 Gallery

- 単一ページ構成。カテゴリごとにページ遷移させず、タブ/絞り込みで同一ページ内完結
- タブ構成: All / Works / Family / Anniversary
- 初期表示: All(全作品をまとめたグリッド)
- タブ切り替え: フェード等の演出なし、瞬時にグリッドが絞り込まれる
- 実装: ARIAのtablist/tabpanelパターン。矢印キーでのタブ間移動に対応
- URL連動: `/gallery?category=all|works|family|anniversary`。クエリなしアクセスは all 扱い。特定カテゴリを直接リンクで共有可能にする
- 各カテゴリ内は縦横比を揃えた均等グリッドで表示

**作品詳細ページ**
- 作品クリックで単独ページへ遷移し、大きく表示
- 前後の作品への移動: 矢印キー操作とクリックの両方に対応
- 遷移演出(フェード・スライド等)は入れない

### 5.3 Profile

- 写真歴(2013年〜)、被写体への向き合い方、人物像を中心としたテキストベースの構成(既存の要件定義テキストをベースに再構成)
- 展示歴・掲載歴・受賞歴などの実績欄を追加(現時点で実績があるため掲載)。今後の実績追加にも対応できる形でコンポーネント設計する

### 5.4 Contact

- お名前・メールアドレス・お問い合わせ内容(フリーテキストのみ)のミニマルなフォーム
- 問い合わせ種別の選択(取材/展示/購入など)は設けない。営業色を出さない方針を最優先
