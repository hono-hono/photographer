## 0. しくみ（これだけ覚えておけば大丈夫）

```
Kuroco で保存 → 約90秒待つ → 自動でビルド（2〜5分） → サイトに反映
```

- サイト: https://hono-hono.github.io/photographer/
- Kuroco 管理画面: サイトキー `hono-portfolio`
- 公開の状況: https://github.com/hono-hono/photographer/actions （緑のチェック = 成功、赤の × = 失敗）
- 続けて何件も保存したときは、最後の1回分だけビルドされます（途中のものは自動で取り消し）

> 💡 **補足**
> 反映されないときは、ブラウザの再読み込み（Mac は ⌘ + Shift + R）を試してください。それでも古いままなら、Actions の結果を見ます（→ 6章）。

## 1. 作品を追加する

**手順**
1. ［コンテンツ定義］→「作品」の行の［追加］
2. 次の項目を入力する

| 項目 | 必須 | 書き方 |
|---|---|---|
| タイトル | ○ | 管理用の名前。サイトには出ない（例: 下津井 旧線路 1） |
| スラッグ | ○ | URL になる。英小文字・数字・ハイフンだけ。**場所名-連番**（例: `shimotsui-line-01`）。他の作品と同じものは使えない |
| カテゴリ | ○ | 仕事の撮影は **Works**、個人の作品は **Personal**。ほかに Family / Anniversary |
| 写真 | ○ | 現像済みの JPEG / PNG / WebP（長辺3000px程度まで）。サイト用の縮小は自動 |
| 代替テキスト | | 画面には出ない短い説明（例: 草に覆われた廃線の線路）。空なら「hono の写真（カテゴリ名）」が入る |
| MVに使う | | トップのメインビジュアルに出すときだけ「使う」（→ 3章） |
| MVの順番 | | MVに使うときだけ 1〜10 |

3. 公開にして［追加する］

> ⚠️ **注意**
> - スラッグは公開後に変えると URL も変わり、共有したリンクが開けなくなります
> - 公開するのは、写っている人の了承が取れている写真だけにしてください（特に Family / Anniversary）

## 2. 作品を直す・消す・並べ替える

- **写真の差し替え**: 作品を開いて写真を入れ替え、更新する。古い写真が残らないよう、URL は自動で新しくなる
- **非公開にする**: 公開設定を非公開にすると、サイトから消える（Kuroco には残る）
- **削除**: 一覧で選んで削除。サイトからも消える
- **並び順**: Gallery は Kuroco の一覧の並び順どおり（今は登録した順）

> ⚠️ **注意**
> MV に使っている作品を消す・非公開にすると、MV が10枚に足りなくなりビルドが止まります。先に別の作品を MV に入れてください（→ 3章）。

---

## 3. トップの MV（10枚）を入れ替える

**ルール**: 「MVに使う」が「使う」の作品が**ちょうど10件**、「MVの順番」が **1〜10 で重複なし**。

**手順（1枚入れ替える場合）**
1. 外したい作品を開き、「MVに使う」を「使わない」にして更新
2. 入れたい作品を開き、「MVに使う」を「使う」、「MVの順番」に空いた番号を入れて更新

> 💡 **補足**
> 1件目を保存した直後は9件になりますが、続けて2件目を保存すれば、最後の保存分だけビルドされるので問題ありません。途中のビルドが失敗の印になっても、最後が成功していれば大丈夫です。

MV の並び: PC は 4枚・3枚・3枚の3行、スマホは2枚ずつ5行。順番1〜4がPCの1行目です。

## 4. カテゴリ（Gallery のタブ）を管理する

**場所**: ［コンテンツ定義］→「作品」の行の［カテゴリ設定］

| やりたいこと | 操作 |
|---|---|
| 追加 | ［追加］からカテゴリ名とスラッグを入れる |
| 名前を変える | カテゴリ名をクリックして編集 |
| タブの順番を変える | 「並び順」の数字を書き換えて［並び順を更新する］。**数字が大きいほど左** |
| 削除 | チェックを入れて［削除する］。先にそのカテゴリの作品を別のカテゴリへ移す |

- カテゴリ名 = タブに出る名前、スラッグ = URL（`?category=works`）
- スラッグは英数字と `_` だけ。`all` は使えない
- 作品が1件もないカテゴリはタブに出ない

**今のカテゴリ**

| カテゴリ | スラッグ | 並び順 | ID | 用途 |
|---|---|---|---|---|
| Works | `works` | 30 | 15 | 仕事で撮影した写真 |
| Personal | `personal` | 25 | 20 | 個人の作品 |
| Family | `family` | 20 | 18 | 家族写真 |
| Anniversary | `anniversary` | 10 | 19 | 記念日の撮影 |

**新規登録で最初から選ばれるカテゴリを決めたいとき（任意）**
1. ［オペレーション］→［カスタム処理］→［追加］
2. 処理に次を書く（`20` は初期値にしたいカテゴリの ID）
   ```
   {if !$topics_id}
     {assign var=form_data.contents_type value=20}
   {/if}
   ```
3. トリガーを［コンテンツの表示（管理画面）］、対象を「作品」にして公開・保存
4. 作品の［追加］を開いて、選ばれているか確かめる（選ばれていなければ書き方の確認が必要）

## 5. 実績・プロフィールを直す

**実績**（［コンテンツ定義］→「実績」）
- 内容（タイトル）、区分（受賞・選出 / 講演・活動 / 資格）、時期（例: 2025年5月、現在。空でもよい）
- 区分の並びは「受賞・選出 → 講演・活動 → 資格」で固定。区分の中は登録した順

**プロフィール**（［コンテンツ定義］→「プロフィール」、1件だけ）
- リード文・写真歴（改行はそのまま反映。太字などの装飾は使えない）
- ポートレート写真とその代替テキスト（**どちらも必須**）

## 6. ビルドが止まったとき

**手順**
1. https://github.com/hono-hono/photographer/actions を開く
2. 赤の × が付いた一番上の実行 → 「build」→「Build」の行を開く
3. `[content] Kuroco のデータに問題があるため、ビルドを止めました。` の下に理由が日本語で出ている
4. Kuroco で直して保存すると、自動でもう一度ビルドされる

**よくある理由と直し方**

| ログの文 | 直し方 |
|---|---|
| スラッグが空です / 英小文字・数字・ハイフンだけにしてください | 作品のスラッグを直す |
| スラッグ「…」が他の作品と重複しています | どちらかのスラッグを変える |
| カテゴリが選ばれていません | 作品のカテゴリを選ぶ |
| カテゴリ「…」が使えません | そのカテゴリが非公開か、スラッグが空。［カテゴリ設定］で直す |
| 写真が登録されていません | 作品に写真を入れる |
| MVに使う作品が N 件あります / MVの順番 N が重複しています | 3章のルールに合わせる |
| プロフィール: …が空です | プロフィールのリード文・写真歴・ポートレート・その代替テキストを入れる |

> 💡 **補足**
> ビルドが止まっても、公開中のサイトは**前の状態のまま**表示されます。急いで直さなくても大丈夫です。

## 7. お問い合わせフォーム

- 受信内容: ［キャンペーン］→［フォーム］→「お問い合わせ」（ID 3）の回答一覧。通知は photographer.hono@gmail.com に届く
- **受付を止めたいとき**: フォームを無効にすると、サイトでは「ただいまフォームでのお問い合わせを受け付けていません」と表示される
- **フォームの設定を保存したあとは、有効のままになっているか必ず確かめる**（以前、編集後に無効になって送信できなくなったことがある）
- 送信は1時間に10回まで（いたずら対策）

> ⚠️ **注意：自動返信メールの文面を直すとき**
> `{if …}{/if}` の直後の改行は1つ消えます。行を空けたいときは、`{/if}` のあとに改行を2つ入れてください。
