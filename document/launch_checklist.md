- [x] 🤖 ダミー画像を用意する（`dummy-photos/` に作品20枚＋ポートレート1枚。作り直しは `python3 scripts/make-dummy-photos.py`）

- [ ] （公開前まで）写真を書き出す（長辺3000px程度までのJPEG。サイト用の縮小は自動）
- [ ] （公開前まで・任意）各写真の代替テキスト（画面には出ない短い説明）を書く。空なら「hono の写真（カテゴリ名）」が自動で入る（2026-11-10 から任意）
- [ ] （公開前まで）ポートレート写真を用意する（PCは縦位置、SPは横長で切り抜いて表示）
- [x] Profile のリード文と「写真歴」の本文（2026-11-01 決定。文面は仕様書 5.4）

- [ ] ココナラのプロフィールの撮影歴「約5年」を「2013年から」に直す

> ⚠️ **注意**

## ステップ6　公開の設定をする 🙋🤖

- [x] 🙋 リポジトリの Settings → Secrets に Kuroco のAPIトークンを登録する（`KUROCO_API_TOKEN`。2026-11-06、管理画面の Swagger UI で発行したもの）
- [x] 🤖 自動公開のワークフローに「Kuroco で更新したら再公開する」きっかけを足す（Kuroco から動かされたときは90秒待ち、続けて保存したときは最後の1回にまとめる）
- [x] 🤖 Kuroco の GitHub 連携に必要な `kuroco_front.json` をリポジトリの直下に置く（2026-11-06）
- [x] 🤖 トークン登録後、Actions を手動で実行して Kuroco のデータでビルドできるか確かめる（2026-11-06 成功。作品20件・MV10件・実績8行、写真21枚を縮小。公開の段階だけ Pages が未設定のため止まった）
- [ ] 🙋 使っていない古いトークン（メモ「GitHub Actions build (KUROCO_API_TOKEN) long-lived」）を削除する（API「hono build」→ Swagger UI のトークン一覧。こちらからの削除は権限の確認で止められた）
- [x] 🙋 Kuroco の［KurocoFront］→［GitHub］で連携する（リポジトリ `hono-hono/photographer`、連携先のワークフロー `deploy.yml`、ブランチ `main`）
- [x] 🤖 保存したら自動公開を動かすカスタム処理を作る（2026-11-06。追加用 `hono_github_deploy_insert`・更新用 `hono_github_deploy_update`・削除用 `hono_github_deploy_delete`。中身は `{github_deploy}` だけ。トリガーは1つの処理に1つしか付けられないため3つに分けた）
- [x] 🙋 3つのカスタム処理に、それぞれトリガー（コンテンツの追加後・更新後・削除後）と対象（作品・実績・プロフィール）を設定し、公開にする
- [x] 🤖 Kuroco で記事を更新して、自動公開が動くか確かめる（2026-11-07 成功。Kuroco から `deploy.yml` が動き、90秒待ってビルドまで成功。公開の段階だけ Pages が未設定のため止まった）
- [x] 🙋 リポジトリを公開（Public）にする（無料プランでは非公開のリポジトリで Pages を使えないため。2026-11-07。公開前にこれまでの記録にトークンなどがないことを確認済み）
- [x] 🙋 **リポジトリの Settings → Pages で、Source を「GitHub Actions」にする**（2026-11-07。自動公開が最後まで成功し、トップと Gallery の表示を確認）

**公開後に増えた作業（2026-11-09〜）**
- [x] 🙋 作品の古い必須項目「カテゴリ」（ラジオボタン）を削除する
- [ ] 🙋 作品の「代替テキスト」の必須を外す（［コンテンツ定義］→「作品」→ 項目「代替テキスト」。こちらの権限では変更できなかった）
- [ ] 🙋 作品カテゴリの初期値を決める（必要ならカスタム処理を作る。手順は運用マニュアル）
- [ ] 🙋 ダミー作品20件を、本物の写真の登録後に削除する

> ⚠️ **注意：Kuroco の支払い方法**
> Kuroco にクレジットカードが未登録のあいだは、メール送信などに1時間あたりの上限がかかります（例: メール送信 100通/時）。無料枠の範囲なら料金はかかりませんが、公開前にカードを登録しておくと安心です（登録は管理画面の［請求］から、スーパーユーザーが行う）。

> ⚠️ **注意：トークン未登録のあいだはビルドが失敗します**
> ダミー写真のまま公開されないよう、`KUROCO_API_TOKEN` がないとビルドを止める設定にしています。登録するまで Actions に失敗の印が付きますが、問題ありません。

> ⚠️ **注意**
> Pages を有効にした時点で、`main` の内容が誰でも見られる状態になります。仮の画像のままのサイトを見せたくなければ、ステップ5が終わるまで有効にしないでください。
